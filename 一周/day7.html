🧠 Day 7 评测与 Harness

🏎️💥🧱 什么是 Harness？(汽车碰撞测试场)

你用前六天造了一辆极其豪华的智能汽车（Agent）。但你怎么证明它安全？你不能只让开发人员下楼开着去买个菜就算测试通过了。

你必须把它开进“碰撞测试中心 (Evaluation Harness)”。在这里，系统会自动让你的车在极端路况跑 1000 次，生成极其精确的量化跑分报告（如防撞率98.5%）。

在 Agent 开发中：

Harness 是一套自动化的评测流水线。它能自动给你灌入 1000 个极其刁钻的用户提问，自动抓取 Agent 的输出，并用算法自动打分，最终生成体检报告。只有数据，才是优化大模型系统的唯一真理。

Harness 与前置核心模块的交响乐

🛡️ 联动 Day 2 (Schema)

指标：格式遵循率

你的 Enum 防得住幻觉吗？Harness 跑 1000 次，统计 JSON 崩溃率。低于 99.9% 就去重写代码！

🔀 联动 Day 4 (Router)

指标：分类准确率

用混淆矩阵排查你的 LLM 分类器会不会把“医疗急救”误判成“天气查询”。

📚 联动 Day 5 (RAG)

指标：Hit@K 检索命中率

Chunk Size 设 512 好还是 1024 好？让 Harness 各跑 500 题对比分数，不要凭直觉瞎猜。

💡 架构师级面试话术 (Eval-Driven)

业余玩家靠肉眼测试 Demo，资深工程师靠 Harness 驱动迭代。

“在一个复杂的 DAG 和多 Agent 协同系统中，牵一发而动全身（比如改了一句 Prompt，可能 Router 变准了，但 RAG 拒绝回答率飙升了）。

因此，只有搭建了完善的自动化 Evaluation Harness 体系，以数据指标（如召回率、格式准确率、无幻觉比例）为唯一准绳，我们才能在迭代核心业务链路时拥有‘安全网’，保障系统在线上的工业级鲁棒性。”
