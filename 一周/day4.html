🧠 Day 4 多智能体协同

从单体到系统：Multi-Agent 架构

单体 Agent 容易“样样通样样松”。工业级的做法是设立多个专业 Worker，并在之上构建强大的调度路由机制。

🔀 Router (路由分发)：交通警察

Router 本身不解决具体问题，它的唯一职责是：理解用户模糊输入，并将任务（State）丢给对应的专业 Worker Agent。单向分发，不负责审核结果。

1. 规则硬路由 (Keyword)

代码层面的正则匹配 (如 `if (input.includes('天气'))`)。速度快零成本，但极其死板，无法理解“穿短袖吗”这种隐式意图。

主流推荐

2. LLM 意图分类器

调用一次小模型做“单选题”。

Schema: { enum: ['weather_agent', 'chat_agent'] }

聪明灵活，结合 Enum 锁死输出选项，完美防止模型乱造 Agent 名字导致系统崩溃。

3. 语义路由 (Semantic Router)

把输入转为向量，去意图向量库里找距离最近的分类。速度远快于调用大模型推理，是大厂高并发网关的高阶玩法。

💡 Router 高阶面试话术

“为了保证路由分发的绝对准确性，我结合了 Few-Shot Prompting 和 JSON Schema 中的 Enum 枚举强约束，迫使充当 Router 的 LLM 只能输出预设合法的 Agent 名称，有效避免路由层产生格式幻觉导致分发崩溃。”

👔 Supervisor (监督者)：严苛的项目经理

与交通警察不同，Supervisor 模式的核心是“带审核的循环反馈 (开会模式)”。它不仅派活，还要盯进度、验质量。

工作流拆解

  1. 接收大单： “查苹果财报并写分析文章”。
  2. 分配与挂起： 派给 Search Agent 查数据，Supervisor 等待。
  3. 打回重做 (核心)： Search Agent 交回数据。Supervisor 审核发现缺少微软对比数据，直接把任务打回让其重查。
  4. 接力流转： 数据合格后，将整理好的 State 交给 Writer Agent。
  5. 终审输出： 文章无误，最终返回给用户。
💡 Supervisor 面试话术 (结合 LangGraph)

“我采用 LangGraph 实现 Supervisor。将其作为核心条件边(Conditional Edge)节点，Worker 执行完数据必须流回 Supervisor 评估。动态决定是重试(触发循环)还是结束流转，极大提升了长链路业务的确定性。”
