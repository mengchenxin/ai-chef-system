前置概念：两大核心引擎与 Token

🔤

什么是 Token (词元)?

大模型阅读的最小“积木块”。1 个英文单词 ≈ 1.3 个 Token，1 个汉字 ≈ 0.5~1.5 个 Token。大模型的计费和脑容量上限全看 Token 数量。所以我们按 Token 数而不是字数来切分文本。

🧠 LLM (大语言模型)

类比：读万卷书的“失忆学者”

他是系统的 CPU，负责推理和包装文字。但他没有记忆，不懂你们公司的私有规定，强行问他就会触发“幻觉”瞎编。

🗄️ 向量库 (Vector DB)

类比：按“含义”排列的图书馆

它是外挂硬盘。把词语变成数学坐标，懂“苹果”和“香蕉”是近义词。专门用来实现语义搜索，为 LLM 提供知识弹药。

RAG：大模型的“开卷考试”

为了不让大模型瞎编，我们在它答题前，先让代码去向量库“抄”正确答案（片段），贴在卷子上让它照着读。

1. Retrieval (检索)

用户提问后，Node.js 拿着问题去向量库，抽出最相关的 3 个文本块。

2. Augmented (增强)

把这 3 个文本块当做“参考资料”，和用户问题一起拼装成超级 Prompt。

3. Generation (生成)

大模型阅读卷子上的参考资料，进行阅读理解作答，实现 0 幻觉输出。

🔪 核心工艺：Chunking (切块)

决定 RAG 生死的最关键步骤。为什么建库前必须把 10 万字切成一小块一小块？

数学底层：大合照 vs 大头贴

向量化是在算文字的平均含义。

  • ❌ 榨汁机/大合照 (不切块)： 把10万人放一张合照里，你要找的张三（特征）就被9万句废话给平均/稀释掉了，根本搜不到这滴“草莓汁”。
  • ✅ 大头贴 (切块)： 每500字拍一张大头贴，语义纯正，一搜“考勤”就能瞬间精准召回张三。

段落大小怎么定？(256~1024)

  • 太小： 丧失上下文代词（“他同意了”）。
  • 太大： 包含废话，重新引发语义稀释。
  • 终极护城河：Overlap (重叠度)。 切割时让每块包含上一块的最后 50 个 Token。就像贴瓷砖的接缝，防止一句话被从中间物理切断导致意思断裂。
