六、 知识注入与 RAG (Day 5)

切块原因：大合照效应

向量化在算“平均含义”。10万字整存就像10万人合照，找1个人系统根本搜不到（被稀释）。切段落就像拍大头贴，实现精准召回。

切块三要素 (Chunking)

太小丧失上下文，太大产生语义噪音。必须设置重叠度(Overlap)，像贴瓷砖的接缝，防句子断裂。

Q1 核心机制 Node.js 是单线程的，为什么能处理极高并发？
▼

核心答案：事件驱动与非阻塞 I/O (基于 libuv 库)。

  • Node.js 的“单线程”仅指执行 JS 代码的主线程是单线程的。
  • 当遇到耗时任务（如读写文件、网络请求、查数据库）时，主线程不会傻等，而是把任务交给底层的 C++ 线程池（通过 libuv 库）去后台处理，主线程立刻去接待下一个用户请求（这就是非阻塞 I/O）。
  • 等后台任务做完了，libuv 会把回调函数扔进事件队列 (Event Queue)。主线程一有空，就会通过事件循环 (Event Loop) 去执行这些回调，把结果返回给用户。

💡 面试官追问防守：如果主线程遇到大量 CPU 密集型计算（如死循环、大视频转码），整个 Node.js 依然会被阻塞卡死。因此 Node.js 适合 I/O 密集型（如高并发接口），不适合 CPU 密集型。

Q2 异步编程 解释宏任务(MacroTask)与微任务(MicroTask)的区别？
▼

在事件循环机制中，队列分为两种，它们的执行优先级不同：

  • 微任务 (MicroTask)： 优先级 极高。
    代表人物：Promise.then(), process.nextTick。
    执行时机：当前操作结束后，事件循环进入下一个宏任务之前，会清空所有微任务。
  • 宏任务 (MacroTask)： 优先级 一般。
    代表人物：setTimeout, setInterval, I/O 操作。
    执行时机：微任务队列清空后，按顺序拉取一个宏任务执行。

结论口诀：同步代码 > process.nextTick > Promise.then > setTimeout

Q3 缓存三大坑 什么是 Redis 的缓存穿透、击穿和雪崩？怎么防？
▼
1. 缓存穿透 (无中生有)

黑客疯狂请求一个数据库根本不存在的ID（如 id=-1）。Redis查不到，就会去查MySQL，MySQL也查不到，压力全压垮数据库。

解决：对空结果也缓存（设置极短过期时间）；或使用布隆过滤器(Bloom Filter)提前拦截。

2. 缓存击穿 (一点突破)

一个超级热门的 Key（比如热搜第一名）突然过期失效，瞬间一万个请求同时砸向 MySQL。

解决：使用互斥锁（Mutex Key），只放一个请求去查数据库并写回缓存，其他请求排队等待。

3. 缓存雪崩 (全线崩塌)

大量的 Key 设置了相同的过期时间，导致在同一时刻大面积失效，或者 Redis 直接宕机，请求洪峰冲垮数据库。

解决：给过期时间加上一个随机数，让它们均匀失效；建立 Redis 高可用集群。

Q4 网络基础 说说常见的 HTTP 状态码及其含义？
▼
2xx (成功)
  • 200 OK: 请求成功。
  • 201 Created: 成功且创建了新资源。
3xx (重定向)
  • 301: 永久重定向。
  • 302: 临时重定向。
  • 304 Not Modified: 走浏览器缓存。
4xx (客户端错误)
  • 400 Bad Request: 参数格式有误。
  • 401 Unauthorized: 没登录/没Token。
  • 403 Forbidden: 登录了但没权限。
  • 404 Not Found: 接口不存在。
5xx (服务端错误)
  • 500 Internal Server Error: 代码报错了。
  • 502 Bad Gateway: 网关/代理报错。
  • 504 Gateway Timeout: 处理超时。
