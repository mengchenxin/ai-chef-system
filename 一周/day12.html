二、 Day 1 核心：智能体的推理与决策机制

面试官最关心的首要问题：你是否理解 Agent 是如何思考和行动的？本节通过交互式选项卡，详细拆解了工业界最常用的三种推理策略。点击下方标签页探索不同的工作流机制。

🔄 ReAct (Reason + Act) 基础运行逻辑

工业界最基础的 Agent 运行逻辑。大模型不能直接执行动作，必须先输出思考过程。在 Node.js 中，这本质上是一个被代码控制的 while 循环状态机。

1. Thought (思考)
模型分析现状，决定下一步动作。
➔
⬇
2. Action (行动)
模型输出需要调用的工具和参数。
➔
⬇
3. Observation (观察)
Node.js 执行工具后，返回结果给模型。

📋 Plan-and-Solve (计划与解决)

针对宏大或复杂任务的策略。核心动作是**任务拆解 (Task Decomposition)**。

阶段一：大模型 Planner

让大模型作为 Planner，输出包含多个子任务的结构化 JSON 数组。

[ {"step": 1, "task": "搜索相关资料"}, {"step": 2, "task": "提取关键数据"} ]
阶段二：Node.js Executor

Node.js 作为 Executor，维护一个任务队列，调度底层的 Worker Agent 逐一执行子任务，汇总结果。

🛡️ Self-Reflection (自我反思与纠错)

区分玩具项目与工业级系统的关键：为 Agent 添加系统级异常捕获机制。应对外部 API 崩溃、工具调用超时、大模型参数解析失败等痛点。

兜底策略 (Node.js 层面)

绝对不要将错误直接抛给用户。Node.js 捕获异常后，将错误信息（Error Stack）或自定义提示词封装成 Observation，附加“执行失败，请分析原因并重试”的指令，再次提交给大模型，触发其自我纠正。

三、 Day 2 核心：工具调用 (Tool Calling) 极致工程化

如果说 ReAct 是 Agent 的大脑，那么 Tool Calling 及其背后的 JSON Schema 就是 Agent 的手脚和数据契约。本节包含了概念对比、代码结构解析以及一个交互式错误诊断器，帮助您理解如何处理模型约束失败的情况。

核心控制维度对比

🗣️
Prompt (提示词)

给大模型“洗脑”的自然语言，决定模型怎么思考。它是灵活的、逻辑驱动的。

📄
Schema (数据模式)

代码与大模型的“数据契约”，特指 JSON Schema，决定模型怎么向 Node.js 输出结构化数据。它是死板的、严谨的、不可违背的。

JSON Schema: Tool Definition 实战解剖

get_current_weather.json 
{
  "type": "function",
  "function": {
    "name": "get_current_weather", # 后端的路由 Key，必须唯一且无空格
    "description": "获取指定城市的天气...", # 隐形的 Prompt，告诉模型何时调用
    "parameters": {
      "type": "object",
      "properties": {
        "location": {
          "type": "string",
          "description": "城市或地区的名称"
        },
        "unit": {
          "type": "string",
          "enum": ["celsius", "fahrenheit"], # 枚举防抖：强制模型只能在选项中选择
          "description": "温度单位"
        }
      },
      "required": ["location", "unit"] # 必填项防漏：防止 Node.js 获取 undefined
    }
  }
}

2.5 核心串联：大脑与手脚的协同闭环

你问到了最关键的问题：前两天的概念是如何在一起工作的？我们把 Day 1 的“大脑推理”和 Day 2 的“数据契约”融合到一个真实的 Node.js 请求生命周期中。

1. 规则下发 (Node.js)

Node.js 构造请求体：用 Prompt (Day 2) 设定 ReAct 思考规则，用 Schema (Day 2) 提供可用工具列表，发给大模型。

1
messages.push({ role: 'system', content: 'You must ReAct...' }); tools = [get_weather_schema];
"Thought: 我需要查天气..." tool_calls: [{ name: "get_weather", args: {...} }]
2

2. 决策与行动 (LLM)

大模型根据 Prompt 产生 Thought (Day 1)，并匹配合适的 Schema，输出严谨的 Action (Day 1)。

3. 执行与兜底 (Node.js)

Node.js 拦截 Tool Call 并执行本地代码。出错则利用 Self-Reflection (Day 1) 生成报错提示词；成功则生成 Observation (Day 1)，并重新发起网络请求。

3
try { result = await getWeather(args); } catch (e) { observation = "执行失败: " + e; }
"Thought: 拿到数据或报错，总结/重试。" "Content: 北京天气晴朗..."
4

4. 闭环输出 (LLM)

大模型收到带有 Observation 的完整上下文，跳出循环并最终输出人类可读的答案。

结论：没有 Prompt 和 Schema，ReAct 循环根本无法启动；没有 ReAct 和反思机制，Schema 定义得再好也只是一次单向调用。它们在 Node.js 中被一次 while 循环紧紧绑定在了一起。
